## Was die Quellen belegen

- [GitHub: Repository-Suche](https://docs.github.com/en/search-github/searching-on-github/searching-for-repositories): Ohne `in:` werden Name, Beschreibung und Topics durchsucht. Für README-Inhalte ist `in:readme` verfügbar. Eine ausführlichere README allein erweitert somit nicht alle normalen GitHub-Suchtreffer.
- [GitHub: Topics](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics): Relevante Themen helfen beim Finden und thematischen Browsen; höchstens 20, kleingeschrieben mit Bindestrichen.
- [Google: SEO-Grundlagen](https://developers.google.com/search/docs/fundamentals/seo-starter-guide): Hilfreiche Texte, beschreibende Überschriften und verständliche Bildbeschreibungen unterstützen Suchmaschinen und Leser. Verwandte Formulierungen können natürlich vorkommen; nicht jede Wortvariante muss wiederholt werden. Indexierung und Platzierung sind nicht garantiert.

Unsere Empfehlung ist daher eine kurze funktionsbezogene Beschreibung, passende Topics und konkrete zweisprachige Erklärungen. Keine Suchwortlisten im Nutzertext, fremden Produktnamen als Köder oder versteckten Inhalte. Titel und Beschreibung des gerenderten GitHub-Webauftritts werden teilweise von GitHub bestimmt; wir können dort keine eigenen HTML-SEO-Tags oder robots.txt setzen.

## Wirkung beobachten

[Insights → Traffic](https://github.com/Hendrik4K/DesktopBubbles/graphs/traffic) zeigt mit entsprechendem Zugriff Besucher, Aufrufe und vollständige Klone der letzten 14 Tage sowie beliebte Inhalte und verweisende Seiten. [GitHub-Dokumentation](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository).

1. Den Änderungszeitpunkt notieren und die verfügbaren Werte zunächst als Ausgangspunkt sichern. Die 14-Tage-Zeiträume überlappen; Summen nicht einfach addieren.
2. Nach einer und zwei Wochen vergleichbare Zeitfenster ansehen. Aufrufe und eindeutige Besucher getrennt betrachten. Traffic verwendet UTC; Besucher/Klone aktualisieren stündlich, Verweise täglich.
3. Eigene Prüfungen, einen geteilten Beitrag und Veröffentlichungen als mögliche Einflüsse vermerken. Keine automatisierten Such- oder Besuchsschleifen zur Erzeugung von Traffic.
4. Release-Downloadzähler getrennt beobachten. Downloads und Klone entsprechen weder eindeutigen Personen noch aktiven Installationen.

Traffic liefert keine Suchbegriffe oder Suchpositionen. GitHub schließt Suchmaschinen und GitHub selbst aus den verlinkbaren Verweisen aus. Fehlende Verweise beweisen deshalb keinen fehlenden Suchtraffic. Ein Anstieg nach einer Textänderung beweist keine Ursache. Eine spätere eigene Website könnte separat in Google Search Console verifiziert werden; für dieses Repository wird keine Verifizierung vorgetäuscht.
